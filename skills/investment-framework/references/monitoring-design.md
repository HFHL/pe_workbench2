# 失效条件设计：把“什么情况下我们错了”变成可执行检查

失效条件（`F`）不是风险提示，而是**下一次跟踪运行要逐条执行的检查项**。写得含糊，跟踪就只会复述报告；写得可观测，跟踪才能告诉你“哪条观点该降级”。

## 一条好的失效条件长什么样

```
F2 ｜ T1 ｜ 季度 DRAM 合约价（主流 DDR5 8Gb，月度均价）
   ｜ 环比连续两个季度下跌 ≥5%
   ｜ TrendForce/集邦月度报价 ｜ quarterly
   ｜ 预警：单季环比 -3% ｜ 触发：连续两季 -5%
   ｜ 动作：核对库存与稼动率，下调 2027 ASP 假设，重算 V1
```

五个要素缺一不可：

1. **指标**：可观测、有口径、有单位。
2. **阈值**：具体数值或明确事件，并写明依据。
3. **来源**：谁发布、多久一次、能否拿到历史。
4. **方向**：大于/小于/连续/突破，避免“恶化”这类无法判定的词。
5. **动作**：触发后核验什么、改哪个假设、重算哪个估值、观点降到什么状态。

## 三类信号，三种动作

| 类型 | 例子 | 应该做什么 |
|---|---|---|
| 单期偏差 | 本季毛利率比模型低 1.5pct | 记录，不自动改长期假设；判断是时间错配还是趋势 |
| 持续偏离 | 连续 2–3 期低于假设且缺口扩大 | 下调假设、重算估值、观点可降为 `weakened` |
| 机制被推翻 | 关键技术路线被替代、大客户流失、监管禁止 | 观点 `invalidated`，重写机制而不是微调数字 |

不要在一条 F 里混三种动作。阈值设计要匹配类型：单期用容差，持续用连续期数，机制用事件。

## 阈值怎么定

优先级从高到低：

1. **模型临界值**：估值对某输入不敏感的区间边界（如毛利率跌破 30% 后目标价低于现价）。
2. **历史波动**：用过去 8–12 个季度的分布，取正常波动之外（如 ±1.5σ），不是拍脑袋 ±10%。
3. **经营约束**：产能利用率、合同价下限、现金成本线。
4. **明确约定**：用户指定或投委会规则。

没有依据时写“待定”，并在 `G` 里记录“需要什么数据才能定阈值”。不要为了显得完整编一个数。

## 频率匹配发布节奏

- 财报科目 → `quarterly`（A 股/港股/美股按各自报告期）。
- 月度行业数据（价格、出货、库存）→ `monthly`。
- 事件型（获批、招标、诉讼、管理层变动）→ `event`，用公告或新闻触发。
- 日频行情只用于价格条件对照，不拿股价波动改经营判断。

频率写错会导致两种失败：太密（每次都被噪声触发）和太疏（错过机制变化）。

## 领先指标与滞后指标

优先选**领先**或**同步**指标，少用滞后确认：

- 领先：订单、排产、合约价、渠道库存、招标、产能建设进度。
- 同步：出货量、份额、单价、毛利率。
- 滞后：收入确认、净利润、现金流。

如果只能用滞后指标，就在 `action` 里写清“确认后如何区分一次性与持续性”。

## 按商业模式选指标

| 类型 | 典型失效信号 |
|---|---|
| 周期品 | 价格环比、库存天数、行业稼动率、新增产能投放 |
| 成长/平台 | 用户/客户数增速、留存、ARPU、获客成本、份额 |
| 制造 | 产能利用率、良率、单位成本、资本开支进度 |
| 项目/订单型 | 中标金额、在手订单、交付验收、回款周期 |
| 金融 | 净息差、不良率、拨备、资本充足率 |

不要给所有公司套同一组指标。

## 常见错误

- **把风险当失效条件**：“竞争加剧”无法判定。改成“主要竞品同规格产品降价 ≥10%”或“公司份额连续两季下降”。
- **阈值没有依据**：默认 ±10% 是最常见的偷懒。
- **只写指标不写动作**：跟踪运行不知道触发后该改什么。
- **一条 F 关联太多观点**：无法判断是谁错了。共享机制时拆成多条，或明确主观点。
- **忽略数据不可得**：写“月度份额”但只有季度数据，跟踪时只能标 `unknown`。
- **把价格下跌当失效**：价格是结果，不是机制。价格条件放第 5 节。

## 交付前自查

- [ ] 每个 `active` / `weakened` 观点至少 1 条 `armed` 的 F。
- [ ] 每条 F 有指标、口径、阈值、来源、频率、动作。
- [ ] 阈值写了依据；没依据的标“待定”并进 `G`。
- [ ] 三类信号没有混在一条里。
- [ ] 至少有一条 F 指向**核心机制**，而不只是财务结果。
- [ ] 触发动作能落到具体假设 ID 和估值 ID。
